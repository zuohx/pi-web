# Tauri 打包计划（pi-web）

## 目标

本项目第一阶段的目标非常明确：

> **先用 Tauri 给现有 `pi-web` 套一个桌面壳。**

首版目标只有三个关键词：

- **套壳**
- **原样运行**
- **不要浏览器**

也就是说：

- `Tauri` 负责提供桌面窗口
- 现有 `pi-web` 继续按当前方式运行
- 用户不再通过浏览器访问，而是通过独立桌面窗口使用应用

本次工作的目标不是改变应用能力，而是改善使用入口与分发方式：

> **让用户像打开普通桌面应用一样打开和使用 `pi-web`。**

---

## 首版约束

首版必须遵守以下约束：

> **直接复用现有生产启动方式，不引入 `standalone` 改造。**

具体来说：

- 继续复用现有生产启动链路
- 不引入 `standalone`
- 不改变现有 API / SSE / Agent 实现
- 不额外设计新的前后端通信方式
- 不把现有逻辑迁移到 Rust / Tauri

首版只解决一件事：

> **让现有 `pi-web` 在 Tauri 窗口里跑起来，并且用户不需要浏览器。**

---

## 允许的改动范围

首版允许进行以下改动：

- 可以修改 `bin/pi-web.js`
- 可以新增 `bin/pi-web-desktop.js`
- 可以新增 `src-tauri/`
- 可以增加桌面模式环境变量
- 可以增加 Tauri 启动与退出清理逻辑
- 可以增加桌面打包相关脚本和配置
- 可以增加服务 ready 判定逻辑

这些改动仅用于：

- 让 Tauri 能启动现有项目
- 让现有项目不要再自动打开浏览器
- 让桌面窗口关闭时后台服务同步退出

---

## 明确禁止项

首版 Tauri 套壳阶段，**不做**以下改动：

- 不重构 `app/api/**`
- 不调整 `lib/rpc-manager.ts`
- 不调整 `lib/session-reader.ts`
- 不修改现有前端请求路径
- 不把现有 API 改成 Tauri commands
- 不把文件读写迁移到 Rust
- 不把 SSE 替换成 Tauri event bridge
- 不为了打包去改 UI 结构

如果某个方案需要触碰以上内容，说明它已经偏离首版目标。

---

## 当前推荐实现选择

首版默认采用以下实现方式：

- 继续复用当前 `next start` 生产启动方式
- 新增 `bin/pi-web-desktop.js` 作为 Tauri 专用启动入口
- `bin/pi-web-desktop.js` 只负责静默启动现有服务，不打开浏览器
- Tauri 负责启动这个入口并加载本地地址
- 不新增第二套服务端实现
- 不引入 `standalone`

这个选择的核心原则是：

> **只增加一个桌面启动入口，不改现有应用实现。**

---

## 两步实施

### Step 1：新增桌面模式启动入口

目标：

- 新增 `bin/pi-web-desktop.js`
- 保持现有 `next start` 生产启动方式
- 禁用自动打开浏览器
- 支持被 Tauri 在后台静默拉起

涉及范围：

- `bin/pi-web-desktop.js`
- 必要时少量调整 `bin/pi-web.js`

### Step 2：接入 Tauri 外壳

目标：

- 新增 `src-tauri/`
- Tauri 启动本地 `pi-web` 服务
- Tauri 窗口加载本地地址
- 关闭窗口时清理后台进程

涉及范围：

- `src-tauri/**`
- 桌面构建相关配置

---

## 必须处理的 3 个问题

首版实现时，必须明确处理以下问题：

### 1. 浏览器自动打开必须禁用

桌面模式下不能再自动打开系统浏览器。

### 2. Tauri 必须等待服务 ready

Tauri 不能盲目立刻加载页面，必须在服务 ready 后再打开窗口内容。

### 3. 应用退出时必须清理后台服务进程

关闭桌面窗口后，后台 Node 服务不能残留。

---

## 运行形态

首版桌面版运行流程：

1. 用户双击 Tauri 应用
2. Tauri 在后台启动 `bin/pi-web-desktop.js`
3. 该入口启动现有 `pi-web` 服务
4. 服务以“不自动打开浏览器”的模式运行
5. Tauri 窗口加载本地服务地址
6. 用户直接在桌面窗口中使用 `pi-web`
7. 用户关闭应用时，后台服务一起退出

---

## 独立桌面应用的含义

首版“独立桌面应用”的含义是：

- 用户看到的是一个桌面应用窗口
- 用户可以双击启动它
- 用户不需要手动打开浏览器
- 用户不需要理解内部仍然是当前项目在本地运行

这里强调的是：

> **独立桌面应用 = 独立窗口体验**

而不是要求第一版必须追求“单个物理 exe 文件内嵌全部内容”。

---

## 最小成功标准

满足以下 4 条，即可认为首版 Tauri 套壳成功：

- 双击 Tauri 应用后能打开 `pi-web` 窗口
- 用户全程不需要手动打开浏览器
- 现有核心功能可正常工作
- 应用关闭后不会残留后台服务进程

---

## 非目标

第一版暂时 **不处理** 以下事项：

- 不引入 `standalone`
- 不重构现有实现
- 不迁移 API / SSE / Agent 到 Rust
- 不把现有 Node 逻辑改写为 Rust
- 不改造前端为 Tauri 专用架构
- 不做 UI 结构调整
- 不做额外桌面能力扩展（如托盘、自动更新、多平台统一方案）

---

## 下一步

按本计划，下一步应直接进入编码实现：

1. 使用 `bin/pi-web-desktop.js` 作为 Tauri 专用启动入口
2. 初始化 `src-tauri/`，并让它启动该入口
3. 在 Tauri 中处理 ready 等待与退出清理

首版判断标准不是“架构是否优雅”，而是：

> **现有项目是否已经被 Tauri 成功包起来，并且用户不再需要浏览器。**
